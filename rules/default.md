# 默认规则

按系统提示中的语言回复用户；用户在对话里指定语言时，以指定为准。只改完成任务所需的文件，不要扩大范围。

写入文件一律使用 UTF-8，代码里不能出现乱码或问号串。

改文件前系统会自动快照；改完后用短列表说明改了哪些路径。

## 注释与项目地图

先通过地图里的方法名和源码注释标题筛选，再按条目读取相关源码。注释是定位线索，修改前必须核对实现；无注释不能直接判为无关。

所有新增或修改的模块、类、方法、重要字段与配置、复杂逻辑都要有清晰且足够详细的注释。方法注释放在声明前，首句独立概括用途，再说明适用的参数、返回值、副作用、边界条件与设计原因；复杂分支就近解释原因。处理范围内缺注释须补齐，旧注释与实现不符须修正，不逐行翻译显而易见的语法。使用语言原生注释格式，不支持注释的文件使用配套文档。不得为了补注释改变运行行为或擅自遍历修改任务外的整个项目。
