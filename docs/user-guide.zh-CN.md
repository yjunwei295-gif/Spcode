## 1. 用途与运行条件

SimpleCode 把聊天与真实项目目录连接起来。助手通过 SpCode 工具读取实现、检索符号、梳理依赖、编辑文件、执行命令，再核对实际结果。配置对应能力后，也能操作 Windows 软件、生成媒体、制作可交互的代码作品。

Windows 安装包包含 Electron 和应用运行时，普通使用无需安装 Node.js。模型另行准备：可用在线 API/账号、支持的 SDK 登录，或兼容的本地权重。软件安装包不附赠厂商订阅，也不包含大模型权重。本地推理需要足够内存和显存。

适合看懂旧项目、定位游戏镜头或 UI 问题、实现限定范围的功能、运行构建测试、制作交互说明，以及处理需要看屏幕的软件操作。任务应说明触发条件、预期结果、不能改的范围与验收方式。只想分析时，明确说明“只读，不改文件”。

## 2. 安装和更新

1. 打开 GitHub 最新 Release，展开 Assets。
2. 下载 `SimpleCode-Setup-1.0.4.exe`。自动生成的 Source code 压缩包是源码，不是安装程序。
3. 完整退出旧 SimpleCode，包括桌宠等仍在运行的窗口。
4. 运行安装程序，选择目录。更新已有安装时使用原目录。
5. 从桌面或开始菜单快捷方式启动。
6. 配置可用模型，再打开目标项目。

本地打包还会生成 `dist/SimpleCode-Portable-1.0.4.exe`。本次线上 Windows 附件为安装版，不代表 dist 中每个文件都已上传。本地推理、生图或 OCR 初次使用可能另行下载引擎、配套文件。

设置和会话通常保存在应用用户数据目录。改源码、提交 Git、上传安装包都不会替换已经运行的进程。更新后需要完整退出、安装、重新启动；单独刷新页面不能更新主进程和 preload。

准确文件大小和 SHA256 见[发布核对记录](release-1.0.4-verification.md)。Windows 可用 `Get-FileHash -Algorithm SHA256 "下载文件路径"` 计算本地哈希。

## 4. 在线厂商与模型

1. 打开“文件 → 设置”。
2. 在“模型厂商”选择模板，或创建自定义厂商。
3. 填写显示名称、协议、接口地址及所需 Key/账号信息。
4. 按服务情况配置请求超时、重试次数、重试间隔。
5. 点击“测试连接”，再添加或保存。
6. 在“模型列表”选择该厂商，点击“拉取模型列表”。
7. 勾选需要保存的模型。
8. 在“已保存模型”点击“使用”。
9. 点击“完成”，核对输入区模型胶囊。

协议包括 OpenAI 兼容、Anthropic、Gemini、Cursor、Codex、Claude Code 等路径。协议兼容不等于所有模型和模态都可用；地址、模型名、账号权限以实际厂商为准。

设置还包含网络代理、本地模型目录、生图默认参数、命令沙盒及其超时、默认轮数、项目索引状态和能力默认配置。厂商请求超时与项目命令超时控制不同操作，不能混为一谈。

额度可能显示金额、积分、百分比或不可读取。手工钱包是本地估算，不是厂商账单。不同币种和单位保持原样；某些服务本身没有可读取余额接口。

<a id="s5"></a>
## 5. Codex、Cursor、Claude Code

这些入口复用已有服务及认证，不会因为添加厂商而获得付费套餐。

- **Codex**：使用所支持的 SDK/CLI 认证路径，确认账号可访问所选模型。
- **Cursor**：未填 Key 时，SDK 可以打开浏览器登录。实现会诊断套餐限制以及 SDK 与编辑器账号差异，并可发起重新登录。编辑器已登录，不代表 SDK 会话拥有相同付费权限。
- **Claude Code**：选择相应协议，使用该接入支持的本机账号认证。

大脑、总结、代码、规划使用 Cursor/Codex 时，AI 直通自动跟随。项目操作仍走 SpCode 工具，必须依据真实工具结果报告改动和测试。

账号错误应检查原始响应、当前厂商与模型；按提示完成登录或修正 Key 后再发送。地区限制与模型资格由服务方决定。连接测试成功也不代表每个后续请求都能成功。

<a id="s6"></a>
## 6. 本地模型和下载

打开“设置 → 本地模型”，选择模型目录；通过“下载模型”下载，或把兼容 GGUF 放进该目录。下载抽屉显示完成后，再选为聊天模型或挂入模型组合，先用小请求试运行。

文本推理与生图使用不同运行时、不同模型家族。文本 GGUF 放进生图槽位不会自动变成生图模型。首次使用可能下载引擎和配套文件；安装包不包含大权重。

根据内存选择量化、上下文和任务大小。权重文件大小不等于完整运行内存。如果启动失败，保留引擎原始错误，核对模型兼容性及内存/显存。下载完成不能替代推理启动验证。

<a id="s7"></a>
## 7. 模型组合与角色

大脑是当前主对话模型。八个能力槽位包括总结、代码、规划、看图、生图、生视频、生 3D、生文档。引导要求配置总结、代码、规划，同一模型可以兼任，不需要三个独立订阅。面板提供的默认、备用选择按实际配置使用。

在“文件 → 模型组合”或设置中的能力默认项分配模型。先保存可用模型，再配置角色。看图和生成必须匹配相应后端能力，不能只靠角色名称赋予功能。

普通流程可分工规划、实现、核对；AGI/直通改变执行组织方式，不代表每次任务都会调用全部槽位。以实际模型组合和任务活动为准。

<a id="s8"></a>
## 8. 项目、目录和 SSH 入口

**打开项目**：选择项目根目录，文件树和工具围绕这个工作区执行。

**克隆仓库**：填写 Git 地址和本地目标位置。私有仓库需要可用 Git 凭据。

**最近项目**：重新打开已有目录。搬家后需要打开新位置。

**添加文件夹**：文件树标题旁的 + 可以添加另一个明确需要的目录。并不表示电脑上所有目录自动成为任务内容。

**多窗口和标签**：为不同任务区分会话，发送前检查当前工作区。多窗口不隔离实际桌面。

**SSH**：当前入口填写用户名、主机、端口、本地映射路径，返回工作区或连接信息；它是连接检查/本地映射入口，不是完整远程文件 IDE、远程终端或部署服务。

<a id="s9"></a>
## 9. 改代码、方案和导图

好用的任务描述包含现象、预期、约束和验收。例如：“打开这个场景会跳镜头，先找入口和调用方，保留原有时长参数，修改后运行镜头专项。”

项目地图索引模块、符号、注释、源码范围和依赖。工具支持按功能定位、精读实现、定义/调用点查询、精确文本和语义检索。注释与地图摘要是线索，真实源码才是依据。设置中可以同步或删除项目索引。

方案导图展示实施范围与状态，链路导图展示调用走势，上下文导图选择模型历史输入。地图未找到调用点，不等于没有调用者。

普通模式可以审阅方案后使用开工入口；AGI 按当前授权直接执行。停止会中断任务，不会撤销已经保存的文件或已经完成的外部动作。

核对时区分：
- 语法检查：证明解析有效。
- 构建：证明相应编译/打包路径通过。
- 测试：证明覆盖断言通过。
- 运行/UI 检查：证明实际观察到的路径行为。

写入成功、启动命令成功都不等于 Bug 已修复。检查改动文件，区分通过、失败、跳过和未验证项。

## 10. 上下文、附件、草稿和插话

输入 `@` 选择项目上下文，输入 `/` 选择技能。已选项显示为标签。附件入口支持图片、文件、文档和视频，支持剪贴板图片粘贴。格式解析、视觉理解取决于实际格式和模型路径。

“上下文”打开导图筛选，勾选后点击应用。排除上下文与删除历史是不同操作；使用删除入口前核对含义。

“发给 AI 的内容”展示发送前能组装出的内容；联网结果、识别结果和后续工具返回可能在运行时才出现。面板中的单次覆盖不会直接修改对应源码文件。

草稿、附件、引用随会话输入状态保存，提交历史支持浏览以前输入。排队把消息安排到后续执行；任务运行时可插话修正目标或补图，说明此次修正与当前任务的关系。

需要中断时点停止；关闭预览、隐藏桌宠不会停止 Agent。语音入口尚不是完整语音识别流程。

### 联网、文档、表格与剪贴板

包含网址、明确搜索意图、时效信息或官方文档的请求可以触发联网检索；普通本地代码/附件任务无需强制搜索。只有实际检索后，结果才进入任务上下文；发送前预览不能当作已经抓取的证据，应核对引用内容。

读文件工具支持文档、表格内容提取。表格截图可识别行列、合并单元格和数值，再写成 XLSX。WPS 转入工具可以生成 XLSX 后使用默认程序打开，或把制表符文本放进剪贴板，粘到当前活动单元格。TSV 无法表达合并布局，识别数值也需与原图核对。

文件树中的剪贴板面板保留条目并提供清空入口，剪贴板图片导入可保存并分析图片。粘贴前确认目标和活动单元格；剪贴板转入不等于实时 Excel 计算接口。

<a id="s11"></a>
## 11. AGI 桌面操作

打开项目、选好模型，在目标会话开启 AGI。工具可以列出和聚焦窗口、读取本地 OCR/UI 自动化控件、点击、滚动、拖拽与输入；文字不足时可使用视觉识别。

这是真实 Windows 桌面操作。手工操作可能改变焦点、目标位置。执行应遵循观察、动作、核对结果；置顶桌宠挡住目标时需移开。

后台接单要求其他前台软件显示完整单行请求，并以 **请帮我** 开头。连续两次相同观察后接单；本进程同一会话的相同请求只接受一次，修改请求文字可发起下一件事。前台为 SpCode 时不接单；正在执行或绑定标签不活动时暂停监测。

空闲截图/OCR 在本地执行。新请求被接受后才进入模型和工具流程并产生对应费用；执行需要的屏幕信息可能发给所选模型。关闭 AGI 或其窗口会停止监测。危险桌面动作仍适用已有确认机制。

进程内存工具只读，可列进程、模块、区域，读取指定类型或搜索指定地址区间。原始数字不自动代表游戏血量等业务含义；不提供写内存功能。

<a id="s12"></a>
## 12. 桌宠

“宠物”显示或隐藏桌宠，可展开会话窗口，并在外观菜单选择皮肤、比例和眼镜设置。

正文最多三行，在角色上方；当前大脑所属厂商额度显示在脚下。空闲只保留额度，不增加闲聊状态文案。工作 HUD 随真实工具变化，思考和回复分开，命令输出不作为桌宠对话。

外观菜单可开关眼镜、左右和上下微调，实时预览并持久化。眼镜跟随角色动画，不修改原始图集。主窗账户总览与桌宠当前大脑额度范围不同，积分和百分比维持原单位。

隐藏桌宠不会取消任务。要中断执行，应使用对应会话的停止入口。

<a id="s13"></a>
## 13. 图片与媒体生成

给相应生成角色配置兼容模型，描述内容、风格、尺寸和约束。结果位于项目 `generated/`。

**本地图片**：文生图使用提示词；图生图使用附件或参考文件的实际路径。“设置 → 本地生图/图生图”可保存宽高、步数、种子、重绘强度、CFG、采样器、反向提示词和预设。单次明确参数优先，空项沿用模型配方。

宽高以像素计，为 64 的倍数；重绘强度影响参考图改变幅度。种子 0 有效，-1 为随机。可编辑像素预设加入像素风参数和最近邻缩放，但不自动拼动画，也不保证动作/角色连续，固定种子不能替代连续帧验收。

**在线图片**：配置支持的图片 API。MXAPI 有 OpenAI 兼容入口和原生 Nano 异步入口；Nano 提交提示词，轮询任务 ID，再下载完成图片。本地引擎参数不会静默套到不相干的 API 路径。

**视频、3D、文档**：需要对应服务和模型。检查返回格式和实际文件，不能只根据槽位名称认定生成成功。

可编辑图示、网页演示、交互解释优先使用代码作品。详见[本地图片说明](local-image-generation.md)。

<a id="s14"></a>
## 14. 代码作品、配乐和视频

作品先写项目内 HTML/Canvas/SVG，再通过 `present_artifact` 登记标题和明确像素尺寸。聊天卡片或“作品”入口可打开，同一路径再次登记会更新已有作品。

独立预览支持交互和刷新。PNG 下载捕获当前预览状态，源码下载保存原 HTML/SVG，不会自动收齐全部素材做成离线站点。

动画定义确定性的 `window.renderFrame(time, frame, info)`，登记尺寸、帧率、时长，支持播放、暂停、拖动与已有音轨。MP4 由 FFmpeg 按源稿逐帧渲染，不直接录制临时交互状态；需要的变化应先写回源稿。

代码配乐通过 HTML `renderAudio(info)` 与 OfflineAudioContext 输出 WAV。音频分析生成波形/RMS、起音和能量增强候选及时间线；候选与估算 BPM 不等于已确认重拍，需要试听后选择卡点。

代码视频明确尺寸、fps、duration，需要声音时先准备音轨；用明确分镜和选定音乐点组织时间。交付前检查实际预览与导出文件，并试听声音。视频导出需要 FFmpeg；取消目标位置选择不会启动渲染，已开始的导出可以停止。

文件生成成功不证明视觉质量、音乐质量或帧一致性。详见[作品工作台](artifact-studio.md)、[代码音频](code-audio.md)、[代码视频](code-video.md)。

<a id="s15"></a>
## 15. 技能、规则、人设和记忆

技能是可复用任务说明，通过文件菜单或侧栏管理，用 `/` 选择。规则约束持续工作流，人设影响表达；内置默认内容可能为中文。

侧栏提供用户画像和全局偏好。会话工作记忆记录目标、问题和关注文件。这些是提供上下文的记录，不保证全部旧对话每次都会进入模型请求。

可用发送预览检查当前组装内容，只修改自己希望调整的记录。本次发布不修改用户外部身份文件或个人记忆仓库。

<a id="s16"></a>
## 16. 历史、快照和里程碑

历史可重开会话，自动保存和输入状态持久化保留草稿。上下文筛选改变后续输入，不必删除底层历史。

文件变更记录覆盖读写工具及被跟踪命令观察到的变化。快照保留可审阅的旧内容，侧栏可设置数量上限。恢复是单独的用户界面操作，停止不等于恢复，助手不应静默丢弃已有改动。

里程碑记录关键进度，与对话和 Git 互补。任何一种记录都不能独自证明打包或部署成功，还应核对实际产物、提交和运行证据。

<a id="s17"></a>
## 17. 数据、隐私与费用

安装版数据通常位于 `%APPDATA%/SimpleCode`，包括设置、会话、草稿和诊断记录。默认模型目录在用户数据下，也可另选。项目目录按功能保存生成媒体/作品、快照、方案/导图和里程碑等。

长时状态和 JSONL 归档保存在用户数据目录 `long-alive` 下，完整结果留磁盘，内存只加载有界上下文。

在线请求可能包含必要源码、附件、历史、工具结果和任务相关屏幕信息。本地与在线混合模型不等于全离线；空闲本地 OCR 与后续联网执行是两个阶段。

费用取决于实际厂商和模型；定时检查会重复调用模型，可能持续计费。手工余额是估算。公开仓库时不要把凭据、私人用户数据、缓存或权重一起提交。

## 18. 故障排查

| 现象 | 检查位置 |
| --- | --- |
| 没有响应 | 厂商地址、协议、Key/登录、当前模型、原始错误 |
| 只有某模型失败 | 模型权限、地区、模态、目录中的实际名称 |
| Cursor 套餐/账号提示 | SDK 与编辑器账号、付费权限、提示的登录流程 |
| 本地启动失败 | 模型兼容、引擎配套、内存/显存 |
| 生图引擎下载失败 | 指定引擎/伴随文件下载，与聊天认证分别看 |
| 长时任务无法开启 | 项目、模型、当前标签、目标和数值参数 |
| 长时任务暂停 | 超时/错误、切标签、重载/关闭、休眠、未完成退出 |
| 源码改了界面没变 | 完整重启主进程/preload，刷新页面不够 |
| 安装版没有新功能 | 退出、安装新 EXE、启动更新后目录 |
| MP4 导出失败 | FFmpeg、素材、尺寸/fps/时长、渲染错误 |
| 桌面点错位置 | 前台、焦点、坐标、遮挡及动作后结果 |
| 没有余额 | 当前大脑厂商及其余额接口 |
| SSH 不像远程 IDE | 当前只有连接/本地映射入口 |
| 英文仍有中文面板 | 翻译尚不完整，可按本手册原标签定位 |

反馈时给出版本、实际/预期结果和原始错误；失败和跳过项应保留到解决或明确记录。

<a id="s19"></a>
## 19. 长时存活

1. 打开目标项目，选择模型，保持目标会话为当前标签。
2. 点击输入区下方“长时存活”。
3. 填写“长期目标与允许执行的范围”。
4. 设置“检查间隔（秒）”“单轮超时（秒）”，各为 1–86400 秒。
5. 点击“保存并开启”。
6. 检查真实状态、下次检查和最近进度；“刷新状态”重新采样。
7. 点击“停止”停止调度并取消当前自动轮。

SpCode 要保持运行，电脑不能休眠，目标标签活动且其他工作空闲才调度。忙碌只延后、不积压；切换会话暂停原任务，关窗、页面重载或渲染退出会取消调度和在途执行。软件退出后没有后台服务继续跑。桌面动作另需 AGI。

间隔从上一轮结束起算，重复开启不会多建定时器，执行中不能再开并发副本。超时、执行失败、未完成异常退出或状态写入失败会暂停，不静默重复结果不确定的外部动作。

“任务目标导图”复用现有方案图展示目标、进度、调度，不提供源码方案删除。“上下文记录导图”复用对话图，分页、勾选、应用；取消勾选不删除归档。每页/已选历史最多 20 轮，预览和续做进度最多保留末尾 6000 字，完整结果存在 JSONL。新进度和历史手选可保留。

界面仅保留最近自动消息对，普通聊天保留；自动轮不消费未发送草稿、附件、引用、提示词覆盖，也不覆盖手动工作记忆。

内存区分 RSS、JS 堆、外部内存和 Electron 进程，不包括所有外部软件。短测不证明连续数天无泄漏。此功能提供定时执行基础，不附带平台账号、运营策略或社交平台发布集成；停止不能撤销已完成发布，中断后先核对外部结果再继续。详见[技术说明](long-alive.md)。

## 20. 源码开发、Git 与发布

### 从源码运行

安装 Git、npm 和当前 Node.js LTS，推荐 Node.js 24；本地推理依赖最低要求 Node.js 20。安装版使用另外自带的运行时。

```cmd
git clone https://github.com/yjunwei295-gif/Spcode.git
cd Spcode
npm install
npm start
```

主进程为 `electron/main.js`，preload 为 `electron/preload.js`，服务位于 `electron/lib/`，界面位于 `renderer/`，打包/发布/测试位于 `scripts/`，文档位于 `docs/`。

### 打包与核对

```cmd
npm run dist:win
node scripts/verify-release.cjs
node scripts/test-long-alive.cjs
node_modules\electron\dist\electron.exe scripts/test-long-alive-ui.cjs
node_modules\electron\dist\electron.exe scripts/test-ui-performance.cjs
node_modules\electron\dist\electron.exe scripts/test-onboarding.cjs
```

dist 中生成安装版、便携版及未压缩程序。发布核对脚本逐字节比对 app.asar 与应用文件，并使用隔离测试数据启动真实 EXE；不等于测试全部线上服务。

仓库有 macOS arm64/x64 ZIP 组装脚本，存在脚本不等于完成 Mac 运行认证；本次 Windows 发布不上传新 Mac 包。Linux 不是本次已验证打包目标。

### Git 与 GitHub

Git 在本地保存源码历史；GitHub 承载远端仓库和 Release 下载。commit 记录选中的源码/文档变化，push 把提交传到远端，tag 标识一个版本修订，Release 在标签上附加说明和二进制下载。

提交前检查 status/diff，运行相关验证，明确选中文件暂存；不要夹带缓存、测试用户数据、个人设置、密钥。提交并推送后，发布与该修订对应的 EXE。大安装包适合放 Release 附件，不应为了下载而塞进普通源码历史。

本仓库 `scripts/publish-release.cmd` 启动发布脚本，从 package.json 读取版本，从 `scripts/release-notes.md` 读取说明，使用本机 Git 凭据且不打印令牌，创建/更新版本 Release 并上传安装包。随后检查 API 状态、大小/哈希及公网下载；进程退出本身不能证明每一步 API 成功。

发布成功更新最新下载入口；用户正在运行的旧程序仍需退出、安装并重新启动。实际验证、失败尝试和未覆盖项记录在[核对文档](release-1.0.4-verification.md)。
