# AGI 后台屏幕接单

打开项目并选好模型，在目标会话开启 AGI。此后不必回主界面发送消息或再说“开始”：
在其它软件的前台窗口显示一行完整请求，例如“请帮我把当前项目的启动报错修好”。
本地读屏连续两次识别到相同请求后，会把它送入开启 AGI 的那个会话执行。

- 触发词是行首的“请帮我”，不是屏幕上出现的任意文本。
- 本次进程内，同一会话相同请求只接一次；改变请求内容可以发起下一件事。
- 前台为 SpCode 时不接单，避免把聊天里回显的旧需求反复执行。
- 只识别前台窗口在显示器上的可见部分；完整请求需要放在一行，不依赖聊天模型猜测换行后的续句。
- 当前实现沿用本地 OCR 文字总量上限，过长的完整行不会截半句执行。
- 任务运行期间暂停后台接单；切离绑定会话时暂停，切回后继续。
- 接单不清空输入框，不继承未发送草稿里的附件、引用或历史编辑操作。
- 关闭 AGI、关闭绑定窗口立即停止后台接单，在途观察结果也不会继续派发。
- 保存着 AGI 开启状态时，重启后等主界面恢复真实会话再开始待命。
- 删除、发送等桌面危险操作仍走已有确认，自动接单不改变那些权限。

空闲时只在本机截图、裁剪和 OCR，不调用聊天模型；图像未变化时复用 OCR。
只有新请求实际入队后才启动原有 Agent 请求并消耗聊天 token，执行中用量与普通任务一致。
观察间隔沿用 AGI 的硬件资源档位，不新增独立的模型轮询。
截图与空闲全文不会因为待命而上传；开始执行后仍按原有 AGI 流程向所选模型提供任务所需屏幕信息。

代码修改涉及主进程和 preload，需要重启 SpCode 后在现有窗口生效。
运行专项验收：

    node_modules\electron\dist\electron.exe scripts/test-agi-screen-requests.cjs
